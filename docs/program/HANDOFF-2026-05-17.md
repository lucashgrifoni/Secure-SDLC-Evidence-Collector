## What was done today

### 1. Cross-OS structural-SHA fix (Blocker 1 from yesterday's evidence pack)

Snapshot test `test_sample_release_bundle_sha256_snapshot` was failing on
Windows because `evidence_collector.application.integrity.normalize_bundle()`
hashed `raw.artifact_path` literally, baking the host separator into the
digest. Fixed by:

- **POSIX-normalizing `artifact_path` at hash time** in
  [`src/evidence_collector/application/integrity.py`](../../src/evidence_collector/application/integrity.py).
  The bundle written to disk is unchanged; only the structural hash sees
  normalized paths. Helper `_normalize_raw_paths` supports both the
  current `raw: dict` and a future `raw: list[dict]` shape.
- **Rebasing absolute paths to repo-relative** in
  [`tests/integration/test_bundle_snapshot.py`](../../tests/integration/test_bundle_snapshot.py)
  by passing `artifact_root=repo_root` to `run_pipeline()`. Without
  this, paths like `C:\Users\…\examples\…` (Windows) ≠ `/home/runner/…`
  (Linux CI) even after POSIX normalization.
- **Snapshot fixture bumped** from `34f3025e…` to `a42920b3…` in
  [`tests/fixtures/sample_release_snapshot.sha256`](../../tests/fixtures/sample_release_snapshot.sha256).
  The new digest is identical on Windows and Linux (verified by
  string-replacing `\` → `/` in the raw JSON and recomputing).
- **New unit tests** in
  [`tests/unit/test_integrity.py`](../../tests/unit/test_integrity.py)
  (6 tests) lock the cross-OS behaviour directly, so a regression in
  the helper fails the granular test before the snapshot.
- **CHANGELOG.md** updated with a `### Fixed — 2026-05-17` section
  explaining the digest bump.

### 4. Local gate plumbing fixes (discovered while validating)

These were not on yesterday's list but came up as side effects of
re-running the full local gate set, and each one made an existing gate
brittle:

- **Gitleaks allowlist** in [`.gitleaks.toml`](../../.gitleaks.toml)
  now covers `.venv*`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`,
  `.hypothesis`, `__pycache__` because `gitleaks --no-git` does not
  honor `.gitignore`. Before this, a venv install of `license-expression`
  caused 200 false positives from its bundled SPDX license-key index.
- **`.semgrepignore`** added so `semgrep scan --config p/security-audit
  --config p/secrets` works without an explicit target. Previously
  semgrep-core would exhaust its stack scanning the venv on Windows.
- **Pre-commit `mypy` hook** in [`.pre-commit-config.yaml`](../../.pre-commit-config.yaml)
  now passes `src` as an explicit target (`pass_filenames: false`
  combined with no target args was emitting "Missing target module")
  and adds missing `additional_dependencies`: `typer`, `rich`,
  `fastapi`, `httpx`, `jinja2`, `defusedxml`, `types-defusedxml`. Hook
  is now green for the first time.
- **Pre-commit `check-json` hook** excludes
  `examples/labs/*/artifacts/*.json` because lab fixtures intentionally
  ship malformed SBOMs to exercise tolerant-parser paths.
- **Mixed-line-ending fixes** auto-applied to 9 SARIF/log fixtures
  under `examples/labs/*/` and `examples/sample_release/artifacts/`.
  These are lab evidence files that originally came from a mix of
  scanners on different OSes; the `mixed-line-ending` hook normalized
  them to LF.
